# Orange Note v4.1.4

本次更新改善多 agent 会话复用、文件写入保护和任务管理。保留现有 skill 名称、命令及配置格式，
Python 端不新增依赖。完整变更见仓库的 `CHANGELOG.md`。

## 会话策略

- 每个独立 agent 使用自己的逻辑 ID、网页和内核；同一对话后续继续复用。
- 操作结束不立即关闭网页。BrowserSkill 使用 `--session-idle 5m`，连续空闲约五分钟后回收；
  这是空闲时限，不是网页打开五分钟就强制关闭。一个会话的操作不会续期另一个。
- 用户明确要求时可立即关闭选定会话。过期后保留配置和回执，有新操作再用同一 ID 重连。
- 重复 connect 不刷新已有页面。短暂探测错误保留原页；导航错误不自动重放可执行请求。

## 可靠性修复

- 写入与上传先在临时文件中完成并校验，再原子发布或替换，保护已有文件。
- 执行后关闭通信连接，保留健康内核；修复无关 idle 消息提前结束请求的问题。
- RDS 每次新建检查任务，避免同路径更新后返回旧摘要。
- 新增保守的任务清理：只处理身份、结束状态、结束时间与 PID/进程组检查通过的目录。
- 修正 txt/表格检查、大上传缓冲、Range 下载边界和深度诊断可写状态。

## 使用与验证边界

`prune` 面向整个工作区，会删除合格任务的日志和 artifacts。先 dry-run，再在授权范围内执行。
dry-run 的 `removed` 为 0，候选数用 `eligible`；无法测量释放空间时 `freed_bytes` 为 `null`。
浏览器空闲回收不会主动取消脱离的后台任务；远端内核是否回收取决于 Jupyter 策略。

Windows 本地完整回归、Node 行为测试及部分真实 DCS 场景已验证，详见
`VALIDATION_v4.1.4.md`。最终五分钟设置已读回确认，未重复完整五分钟自动到期实测。
